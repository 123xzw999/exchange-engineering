界面设计：交易终端的信息设计

交易界面是最难设计的界面之一：信息量极大、变化极快、 用户在高压力下操作、错误代价是真金白银。 这一章讲的是如何在这样的约束下做出既好看又好用的界面 —— 核心不是「美观」，而是信息层级与操作容错。

本章回答
交易界面如何在高信息密度下保持清晰与安全
关键产出
布局栅格 · 排印尺度 · 色彩语义 · 组件规范

07.1信息架构：先决定什么最重要

交易终端的屏幕空间是稀缺资源，而候选信息有几十种。 设计的第一步不是「怎么排得好看」，而是排优先级。 判据只有一个：用户在做决策的那一刻，需要看到什么？

图 07-A 经典四区布局。面积分配反映优先级：图表占据最大面积，因为它承载决策依据；下单面板面积不大但位置固定，因为它需要被反复触达；盘口窄而高，因为它是纵向排列的价格序列。

布局的铁律

下单面板的位置在任何情况下都不能变。 用户在高频操作中会形成肌肉记忆 —— 买入按钮在哪、数量输入框在哪。 如果因为行情波动导致布局跳动（比如价格位数变化把按钮挤走）， 用户可能误点。任何会改变下单区布局的动态内容都必须被约束。

07.2排印：让数字成为主角

交易界面的文字 80% 是数字。因此排印的第一原则是： 数字必须用等宽字体。

比例字体（如普通无衬线体）中，1 比 8 窄。 这会导致价格数字在跳动时左右抖动，难以快速比较。 等宽字体（tabular figures）让每个数字占同样的宽度， 整列数字对齐，扫视效率大幅提升。

CSS · 数字排印
/* 关键：tabular-nums 让数字等宽，slashed-zero 区分 0 和 O */
.price, .qty, .pnl {
  font-variant-numeric: tabular-nums slashed-zero;
  font-feature-settings: "tnum" 1, "zero" 1;
  font-family: ui-monospace, "SF Mono", "Cascadia Mono", monospace;
  letter-spacing: -0.01em;   /* 等宽下略微收紧，避免松散 */
}

/* 小数部分弱化 —— 让整数位成为视觉焦点 */
.price .int { color: var(--ink); }
.price .dec { color: var(--ink-3); font-size: .85em; }

/* 数字变化时的闪烁提示：向上绿色、向下红色（涨红跌绿）*/
@keyframes flash-up   { from { background: rgba(47,163,107,.22) } to { background: transparent } }
@keyframes flash-down { from { background: rgba(229,72,77,.22) }  to { background: transparent } }
.tick-up   { animation: flash-up .5s ease-out; }
.tick-down { animation: flash-down .5s ease-out; }

字号层级

交易界面的字号对比不需要像营销页面那么夸张，但层级必须清晰。 一个可用的尺度：

不要超过三级

交易界面信息密度高，字号层级超过三级会显得杂乱。 实践中用「大 / 中 / 小」三级就够， 层级之间的区分更多依赖颜色与字重，而不是字号。

07.3色彩语义：颜色必须承载信息

交易界面的色彩不是装饰，而是语义编码。 用户在扫视时，颜色先于文字被识别。

涨跌色：中国习惯与全球习惯的差异

中国习惯（红涨绿跌）
  • 上涨 = 红色（喜庆、热烈）
  • 下跌 = 绿色
  • 适用于中国大陆用户的股票、期货类产品
  • 红色 #E5484D · 绿色 #2FA36B
欧美习惯（绿涨红跌）
  • 上涨 = 绿色（go、安全）
  • 下跌 = 红色（危险、停止）
  • 国际主流交易平台普遍采用
  • 同一套色值，语义相反
必须做成可配置

这是交易产品里最容易造成灾难性误操作的设计点。 一个习惯红涨绿跌的用户，在国际平台上看到满屏绿色， 可能瞬间理解为「大涨」而做出错误决策。 因此：① 涨跌色必须可在设置中切换； ② 切换时给出明确提示； ③ 颜色不能是唯一的编码方式 —— 必须同时有 +/− 符号或箭头。

状态色与功能色

语义用途设计要点
买 / 做多买入按钮、买盘背景、多头持仓使用涨色系。按钮饱和度要足够高，确保一眼可辨
卖 / 做空卖出按钮、卖盘背景、空头持仓使用跌色系。与买入按钮在色相上必须差距极大
中性 / 信息链接、可点击元素、提示用低饱和的冷色，避免与涨跌色混淆
警示风险提示、强平预警用橙色系，区别于纯红（涨色），避免语义冲突
禁用 / 不可用无权限、余额不足的按钮降低不透明度 + 移除 hover 反馈 + 明确原因提示
暗色主题的一个陷阱

在暗色背景上，高饱和度的红绿会显得刺眼且产生视觉残影 （盯着看久了，移开视线会看到补色）。因此暗色主题下 应当降低饱和度、提高明度： 用 #E5484D 而不是 #FF0000， 用 #2FA36B 而不是 #00FF00。 同时用低不透明度的同色作为背景填充（如 10% 透明度）， 比直接填充纯色更耐看。

07.4数据密度：在有限屏幕里放最多信息

交易用户是「专业用户」，他们需要的是密度而不是留白。 把营销页面的「大留白、大圆角」搬进交易界面，结果是用户要不断滚动才能看到关键数据。

维度营销页面的做法交易界面的做法
行高1.8 ~ 2.01.4 ~ 1.6（表格可到 1.35）
圆角16 ~ 24px2 ~ 6px，甚至直角
内边距32 ~ 48px8 ~ 16px
分隔方式卡片 + 阴影1px 细线，或仅靠行间距
颜色数量3 ~ 5 种2 ~ 3 种（中性 + 涨 + 跌）
动效丰富，强调惊喜克制，只用于数值变化的提示

密度的边界在哪

密度不是越密越好。有三个硬性下限不能突破：

  • 可点击元素的高度 ≥ 28px —— 低于这个值，误触率会显著上升。撤单按钮尤其要注意，误触会造成实际损失。
  • 正文对比度 ≥ 4.5:1 —— 暗色背景上的灰色文字最容易踩这条线。用工具实测，不要凭感觉。
  • 相邻数值至少留 8px 间隙 —— 否则在快速扫视时会读错列。

07.5核心组件：盘口、深度图、K 线

盘口：背景条是核心设计

盘口每一档除了价格与数量，还有一个按数量比例绘制的背景条。 这个背景条让用户不用读数字就能感知买卖力量的对比。 设计要点：

  • 比例相对最大值而非绝对值。如果按绝对值，遇到异常大单时其他档位的条会全部缩成一条线。应当以当前可见档位中的最大量为基准。
  • 方向买盘从右向左、卖盘从左向右，让两侧的条形成对称的「力量对撞」视觉，直观反映买卖压力。
  • 透明度10% ~ 18%。太高会干扰数字阅读，太低则看不见。
  • 更新不做过渡动画。盘口每秒变化多次，动画会导致视觉滞后与抖动，反而降低可读性。

深度图：面积图而非折线图

深度图展示「不同价格下的累计挂单量」，它必须用面积图 —— 因为用户关心的是「吃掉多少量能把价格推到某个位置」， 这正是面积（积分）的含义，而不是某一点的值。

一个常见错误

很多深度图用折线连接离散的价位点，结果曲线看起来平滑， 但实际含义被扭曲了。正确做法是阶梯状（step）绘制 —— 因为订单簿的累计量在价位之间是恒定的，只在跨越价位时跳跃。 用阶梯线才能真实反映「吃穿一档后的价格变化」。

K 线：不要重新发明

K 线图有几十年的行业惯例，用户已经形成强预期。 设计上的自由度很小，重点在于：

  • 实体与影线的比例要克制 —— 实体宽度约为周期的 60%~75%，太宽会让密集的 K 线糊成一片。
  • 十字光标必须实时显示数值 —— 鼠标所在位置的价格、时间、对应 K 线的 OHLC。这是高频使用的功能。
  • 持仓成本线要常驻 —— 用户最关心「我什么时候回本」，这条线比任何指标都重要。
  • 委托单标记 —— 在图表上标出未成交订单的价格位置，让用户一眼看到「我的单挂在哪」。

07.6下单面板：最容易出错的界面

下单是唯一一个「点错就真的亏钱」的界面。 它需要比其他所有界面都更强的容错设计。

  1. 买卖必须一眼可辨买入与卖出按钮不能只靠颜色区分（色盲用户无法分辨）。应当同时有文字、位置、形状的差异。买入按钮与卖出按钮的间距要足够大，避免误触。
  2. 数量输入提供百分比快捷键25% / 50% / 75% / 100% 是高频操作。注意「100%」在买单时指的是「用全部可用资金能买多少」，需要按当前价格反算，并留出手续费空间。
  3. 实时显示预计成交额用户输入数量后，立即显示「预计花费 xxx USDT」。这一行数字能拦住大量因为小数点输错导致的错误下单。
  4. 提交前做二次确认（可配置）大额订单或首次交易时弹出确认框，显示完整信息。熟练用户可以关闭确认以提升速度 —— 但要确保这个开关不会被误触。
  5. 提交后立即给出明确反馈按钮进入 loading 态并禁用，防止重复提交。成功与失败都要有明确提示，失败必须说明原因（余额不足？价格超出笼子？交易对暂停？）。
  6. 错误信息要具体「下单失败」是无用信息。「可用余额不足，需要 4320.55 USDT，当前可用 4200.00 USDT」才是有用的。错误信息是产品体验的一部分。
一个被低估的设计

「价格笼子」的提示。当用户输入的价格偏离市场价超过阈值时， 不应只是拒绝，而应该提示「当前市价 43200，您输入的价格偏离 15%， 是否确认？」并给出「使用市价」的快捷按钮。 拒绝只解决了安全问题，提示则同时解决了安全问题与体验问题。

07.7无障碍、暗色模式与设计交付

无障碍不是可选项

金融产品的无障碍有实际的法律与商业意义。关键要求：

  • 对比度正文 ≥ 4.5:1，大字号 ≥ 3:1。暗色主题下尤其要实测，很多「看起来还行」的灰色其实只有 3:1。
  • 色彩不单独依赖颜色传达信息。涨跌必须有符号，状态必须有文字，错误必须有图标 + 文案。
  • 键盘全流程可键盘操作。专业交易者大量使用键盘快捷键，这既是无障碍要求也是效率要求。
  • 焦点焦点环必须可见。用 outline 而不是 box-shadow，且不能被 outline: none 抹掉。
  • 动效尊重 prefers-reduced-motion。闪烁的价格变化对部分用户会造成不适，应提供关闭选项。

暗色模式：交易界面的默认选择

交易界面普遍默认暗色，原因有三个实际考量：

  1. 长时间盯盘的舒适度交易者可能连续数小时盯着屏幕。亮色背景在长时间注视下更容易造成视觉疲劳。
  2. 色彩语义的可辨识度在深色背景上，红绿涨跌色更突出。亮色背景下需要更高的饱和度才能达到同样的辨识度，反而刺眼。
  3. 多屏环境的协调专业交易者常使用多屏，暗色背景在拼屏时视觉干扰更小。
暗色设计的三个要点

① 不要用纯黑。纯黑（#000）与任何前景色的对比都过于极端， 长时间观看会产生光晕感。用 #0A0B0E ~ #14161A 这样的深灰更舒服。

② 层级靠明度而非阴影。暗色下阴影几乎不可见， 应当用背景的细微明度差异（如 #0D0F13 与 #12161C）加 1px 边框来建立层级。

③ 降低大面积高饱和色块。暗色背景下，一块高饱和的按钮 会显得异常刺眼。用降低饱和度、提高明度的方式保持辨识度。

设计交付：让规范可以被执行

设计稿交付后最常见的失败是「实现出来不一样」。 避免这个问题的关键是把设计写成可执行的约束，而不是交付视觉稿。

CSS · 设计令牌
/* 设计令牌：设计与实现共用的唯一事实来源 */
:root {
  /* 表面层级：用明度差异建立层级，不用阴影 */
  --surface-0: #0A0B0E;   /* 页面底 */
  --surface-1: #0D0F13;   /* 卡片 */
  --surface-2: #12161C;   /* 抬起 / hover */
  --surface-3: #171C24;   /* 选中 / 激活 */

  /* 分隔线：只比背景亮一点点 */
  --rule-strong: rgba(255,255,255,.09);
  --rule-weak:   rgba(255,255,255,.045);

  /* 文字：四级足够，且每级都满足对比度要求 */
  --ink-1: #E8EBF0;  /* 主要 · 对比度 14.2:1 */
  --ink-2: #A3ABB8;  /* 次要 · 7.1:1 */
  --ink-3: #737B89;  /* 说明 · 4.6:1 ✓ 刚过线 */
  --ink-4: #4A515C;  /* 仅用于装饰性文字，不承载信息 */

  /* 语义色：降饱和以适应暗色背景 */
  --up:   #E5484D;  /* 涨 · 中国习惯 */
  --down: #2FA36B;  /* 跌 */

  /* 间距：8 的倍数，形成节奏 */
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px;
  --sp-4: 16px; --sp-5: 24px; --sp-6: 32px;

  /* 圆角：交易界面克制使用 */
  --r-sm: 2px; --r-md: 4px; --r-lg: 6px;
}
第 07 章 · 检查清单

① 布局优先级明确，下单面板位置固定不跳动；
② 所有数字使用等宽字体（tabular-nums + slashed-zero）；
③ 涨跌色可配置，且颜色不是唯一的编码方式；
④ 暗色主题不用纯黑，层级靠明度而非阴影；
⑤ 可点击元素高度 ≥ 28px，正文对比度 ≥ 4.5:1；
⑥ 盘口背景条按可见范围最大值比例绘制；
⑦ 深度图用阶梯面积图，不用平滑折线；
⑧ 下单面板有预计成交额、具体错误信息、防重复提交；
⑨ 设计令牌与实现共用，规范可执行。
